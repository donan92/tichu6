# 6T — 브라우저에서 즐기는 6인 티추

HTML, CSS, JavaScript로 만든 정적 웹 게임입니다. 프레임워크, 설치할 런타임 의존성, 게임 백엔드, 시그널링 서버가 없습니다. GitHub Pages에서 그대로 배포할 수 있습니다.

## 실행

개발할 때만 Node.js 22 이상을 사용합니다. `npm install`은 필요 없습니다.

```sh
npm run dev
```

브라우저에서 http://localhost:5173 을 여세요. HTML 파일을 `file://`로 직접 열면 ES module과 WebRTC의 보안 조건 때문에 정상 작동하지 않을 수 있습니다. 실제 이용자는 GitHub Pages의 HTTPS 주소만 열면 됩니다.

## GitHub Pages 배포

1. 이 폴더의 파일을 GitHub 저장소 기본 브랜치에 커밋하고 푸시합니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
3. 소스 브랜치(예: `main`)와 **/(root)**를 선택하고 저장합니다.
4. Pages가 표시하는 HTTPS 주소를 여섯 명에게 공유합니다.

빌드 명령, 환경변수, API 키는 필요 없습니다. `.nojekyll`이 포함되어 있고 모든 리소스 경로가 상대경로라 `/tichu6/` 같은 프로젝트 경로에서도 동작합니다. `server.mjs`는 로컬 파일 미리보기 도구이며 배포 시 실행되지 않습니다. 저장소에 소스를 푸시한 뒤 위 설정으로 GitHub Pages를 활성화하세요. 소스 푸시만으로 Pages 설정이 자동 활성화되지는 않습니다.

## 친구들과 연결

1. 모두 같은 Pages 주소를 열고 닉네임을 입력합니다.
2. 한 명이 **테이블 만들기**를 누릅니다. 방장이 1번 좌석입니다.
3. 방장은 2~6번 좌석마다 별도 **초대 코드**를 만들어 해당 친구에게 메신저 등으로 보냅니다.
4. 친구는 **초대 코드로 참가**에서 초대를 붙여넣고 **응답 코드**를 생성해 방장에게 돌려줍니다.
5. 방장은 응답을 붙여넣고 적용합니다. 6명이 모두 연결되면 시작할 수 있습니다.

같은 기기의 여러 탭에서도 연결을 시험할 수 있습니다. 코드에 네트워크 연결 정보가 포함되므로 해당 친구에게만 보내세요. 새 초대를 만들면 해당 좌석의 이전 초대는 무효가 됩니다. 연습 모드에는 단순한 규칙 기반 봇 5명이 참여합니다.

## 적용한 규칙

- 일반 카드 52장 × 2 + 용·봉·개·새 각 1장 = **108장**, 18장씩 배분.
- 좌석 순서 1~6: **A–B–A–B–A–B**. 순서는 좌석 번호가 증가하는 방향.
- 같은 숫자의 복제 카드도 각각 별도 ID를 가집니다.
- 싱글, 페어, 트리플, 풀하우스, 5장 이상 스트레이트, 2개 이상 연속 페어.
- 숫자 폭탄은 **정확히 4장**. 문양이 같아도 복제 카드 4장이면 허용합니다. 5~8장의 같은 숫자 묶음은 불허합니다.
- 스트레이트 폭탄은 같은 문양으로 연속된 5장 이상. 숫자 폭탄보다 높고, 길이 → 최고 숫자 순으로 비교합니다. 같은 세기의 폭탄은 이길 수 없습니다. 봉으로 폭탄을 만들 수 없습니다.
- 차례 밖 폭탄 가능. 모두 패스하면 마지막 제출자가 **트릭 확정**을 누르며, 그 전에는 폭탄을 낼 수 있습니다. 동시에 도착한 행동은 방장에게 도착한 순서로 처리하며 오래된 상태에서 보낸 요청은 재시도를 요구합니다.
- 새: 선 플레이어 결정, 1로 스트레이트 참여, 2~A 소원. 자기 차례에 소원을 실물 카드로 이행할 수 있으면 반드시 이행합니다. 봉 조합과 폭탄 가능성도 확인합니다. 차례 밖 폭탄에는 소원 의무가 없습니다.
- 개: 선에서만 단독 사용. 두 팀원 중 선택하며, 선택한 팀원이 끝났으면 그 다음 남은 플레이어에게 선을 넘깁니다.
- 봉: 조합에서 2~A 대체. 싱글은 직전 싱글 +0.5, 선이면 1.5. 용은 이길 수 없습니다. 조합에서 대체 숫자를 직접 고를 수 있습니다.
- 용: 최강 싱글, 폭탄에는 패배. 용이 이긴 트릭은 선택한 상대 팀원에게 전달합니다.
- 티추: 자기 첫 제출 전 선언, 개인 1등 성공 시 +100, 실패 −100.
- **이 버전에서 정한 기본값:** 처음 8장만 공개하고 그랜드 티추(±200)를 결정한 뒤 나머지 10장 공개. 팀원 둘에게 한 장씩 동시에 교환. 첫 세 완주자가 같은 팀이면 즉시 트리플 승리 300점. 1,000점 도달 시 높은 팀 승리, 동점은 다음 라운드.
- 일반 점수: 5는 5점, 10·K는 10점, 용 +25, 봉 −25. 더블 덱의 카드 점수 총합은 **200점**. 마지막 사람의 손패 점수는 상대 팀으로, 획득 트릭은 1등에게 이전합니다. 트리플 승리는 카드 점수를 세지 않고 300점을 부여하며 선언 점수는 별도입니다.

공식 Tientsin 변형과 사용자 지정 더블 덱 6T를 구분합니다. 첫 공개 장수, 교환, 트리플 보너스는 더블 덱의 공인 규칙이라고 주장하지 않으며 위 기준으로 고정한 첫 구현입니다.

## 연결과 신뢰 모델

- 방장 브라우저가 권위 있는 상태·셔플·판정을 담당하고, 5개 WebRTC DataChannel을 통해 통신합니다.
- 참가자에게 자신의 손패, 공개된 카드, 상대의 남은 장수만 전달합니다. 상대 손패와 미공개 첫 배분, 교환할 카드는 보내지 않습니다.
- 호스트는 채널로 좌석을 식별합니다. 요청에 실은 플레이어 ID를 신뢰하지 않습니다. 제출 카드는 소유권과 중복, 차례, 조합을 검사하고 상태 revision으로 오래된 요청을 거부합니다.
- 친구끼리 신뢰하는 게임입니다. 방장은 개발자 도구로 전체 패를 볼 수 있고 셔플·상태를 조작할 수 있습니다. 암호학적 분산 셔플이나 방장 치팅 방지는 구현하지 않았습니다.
- 기본으로 Cloudflare(`stun:stun.cloudflare.com:3478`)와 Google(`stun:stun.l.google.com:19302`) 공용 STUN을 사용합니다. 게임 내용을 저장하거나 중계하지 않고 공인 연결 주소를 찾는 외부 서비스입니다. 필요 없으면 입장 전이나 대기실에서 해제할 수 있습니다. 최대 8초 동안 주소를 수집하며, 일부 STUN 응답이 없어도 확보된 주소로 코드를 생성합니다. 공인 주소를 얻지 못하면 같은 네트워크에서만 연결될 수 있다는 안내를 표시합니다.
- **TURN 중계가 없습니다.** 대칭 NAT, 회사망, VPN 등에서는 직접 연결이 실패할 수 있습니다. 모든 인터넷 환경에서 접속을 보장하려면 TURN 서비스가 추가로 필요합니다.
- 활성 연결이 끊기면 진행을 일시 정지합니다. 같은 연결의 일시적 장애가 회복되면 재개되지만, 새로고침·탭 종료 후 재입장, 영구 저장, 방장 자동 이전은 지원하지 않습니다. 게임 동안 탭과 기기를 켜 두세요.
- 가입, 채팅, 결제, DB, 추적 스크립트, 외부 글꼴, 외부 JavaScript 의존성이 없습니다.

## 검증과 구조

```sh
npm test
npm run check
```

- `src/game.js`: 독립 규칙 엔진과 연습 봇
- `src/peer.js`: 수동 offer/answer 및 WebRTC 연결
- `src/app.js`: 한국어 UI, 방장/참가자 메시지 흐름
- `src/style.css`: 반응형 게임 화면
- `tests/`: 규칙, 공개 상태, 라운드 진행 검증

실제 원격 네트워크 6대에서의 연결 가능성은 배포 후 확인해야 합니다. 자동 규칙 테스트가 인터넷 NAT 통과를 보장하지는 않습니다.
