# 6인 티츄 딥러닝 봇 설계·실험 계획

작성: 2026-11-24. 상태: 문헌 기반 제안. 실행 중인 초기 실험과 정식 구현을 구분한다.

## 결론

우선안은 **합법적인 행동별 기대 팀 점수 차이를 학습하는 Deep Monte-Carlo(DMC)**다.
자기 대국으로 결과를 만들고, 신경망이 관측·이력·행동에서 결과를 예측하도록 학습한다.
비교군으로 현재 REINFORCE 실험과 규칙 기반 봇을 보존한다. PPO는 동일 행동 인코딩과
동일 계산 예산에서 비교할 후속 후보다. 큰 Transformer나 검색 알고리즘부터 시작하지 않는다.
DMC의 우월성을 우리 게임에서 입증한 것은 아니다. 아래 평가는 채택 여부를 결정하는 실험이다.

## 현재 구현과 정식 모델의 차이

현재 `research/deep/policy.mjs`는 TensorFlow.js 4.22.0의 62→64→64→32→1 신경망이다.
세 은닉층이 있고, 실제 대국 종료 점수로 REINFORCE 경사 갱신을 한다. 가중치 파일·해시와
갱신 횟수가 저장되므로 수동 계수 탐색과는 다르다. 아직 강한 모델이라는 증거는 없다.

현재 제한:

- 카드 랭크 중심 특징으로 문양 구조와 상세 공개 이력이 빠져 있다.
- 카드 내기/패스만 학습한다. 선언·교환·용 넘기기는 기존 봇, 개 대상·소원도 고정 정책이다.
- 현재 `legalPlays`는 랭크 그룹에서 `slice(0,n)` 등의 대표 조합을 사용한다.
  문양을 달리 보존하는 전략적으로 다른 합법 수를 모두 열거한다고 볼 수 없다.
- 순서 밖 폭탄 판단을 학습 실행기가 별도 호출하지 않는다. 엔진은 허용한다.
- 종료 점수 차이를 ±1로 자르는 초기 보상은 큰 점수 차이를 구분하지 못한다.
- 한 번의 가중치 초기화·기존 봇 중심 비교다. 많은 평가 판수가 독립 학습 seed를 대신하지 않는다.
- 검증 모니터의 16개 짝지은 패는 배선 확인용이다. 출시 판단에는 너무 작다.
- 모델은 런타임 원본 상태를 받되 타인 패의 길이만 읽는다. 정식 모델에서는 타입·입력 경계도 분리한다.

기존 2시간 실행 중 정책·데이터·평가 규칙을 몰래 바꾸지 않는다. 현재 실험은 E0로 남기고,
아래 설계의 실험은 새 버전·별도 데이터 집합으로 시작한다. E0 최종 평가는 마지막 모델과
검증에서 선정된 모델을 구분하고, 검증 최적 모델을 위해 새로운 봉인 평가 seed를 사용한다.

## 게임 환경과 정보 경계 — 먼저 완성할 것

`observe(state, seat)`는 다음 정보만 제공한다.

- 내 카드: 일반 카드는 **4문양 × 13랭크 × 개수(0/1/2)**, 특수 카드는 별도 플래그.
- 라지 티츄 단계에는 처음 받은 10장만 제공. 아직 받지 않은 8장 정보는 모든 특징에서 제외.
- 상대·팀원별 남은 장수, 선언, 완주 순서, 현재 차례, 공개된 수와 패스·획득 점수.
- 내가 보냈거나 받은 교환 카드만 제공. 다른 두 사람 사이의 교환은 제외.
- 공개된 카드의 문양·랭크별 누적 수와 최근 행동 이력. 닉네임·카드 복사본 ID는 학습 특징으로 쓰지 않는다.
- 누적 팀 점수, 목표까지의 거리, 현재 라운드. 후반 승부에 필요한 위험 선호를 학습할 수 있게 한다.

서버의 원본 손패 배열을 모델에 넘기지 않는다. 타인의 카드를 같은 장수로 바꿔도 입력과
결정이 변하지 않는 비간섭 테스트를 둔다. 훈련 시 타인 손패를 쓰는 critic도 첫 버전에는 도입하지 않는다.

행동 생성은 `act()`의 합법성 검증과 별개다. 학습 전 작은 손패의 모든 부분집합을 대조해
누락을 검사한다. 동일 문양·랭크 복사본만 동등 처리하고, 다른 문양 선택은 보존한다.
전체 일반 카드 4장 폭탄, 스트레이트 폭탄, 봉황 대체, 의무 소원, 개 전달, 용 분배를 다룬다.
실행 시간이 너무 길어 후보를 줄일 경우 완전 열거라고 부르지 않고 별도 ablation으로 비교한다.

순서 밖 폭탄은 플레이 직후 끼어들기 기회를 모델에 제공하는 명시적 단계로 모델링한다.
여러 봇의 동시 폭탄 충돌을 처리할 우선순위가 학습·서버에서 동일해야 한다. 평가 때문에
기존 사람의 폭탄 권한이나 게임 규칙을 변경하지 않는다.

## 제안 신경망

```text
내 카드·공개 상태 ── 상태 인코더 ──────────┐
최근 공개 행동 ─── GRU(64) ───────────────┼─ 공통 상태 표현
후보 행동 ─────── 행동 인코더(64) ────────┘
                ↓
       MLP 256 → 128 → 64 → 1
                ↓
      Q(내 관측, 공개 이력, 후보 행동)
                ↓
     합법 후보 중 예상 팀 점수가 가장 높은 수
```

이는 제안 시작점이며 논문에서 우리 게임용 최적 크기로 입증한 값이 아니다.
처음에는 이력 없는 MLP를 비교군으로 두고 GRU가 실제로 도움이 될 때 채택한다.
상태 표현은 후보마다 재계산하지 않고 한 번 계산해 재사용한다. 목표 크기는 10만–50만
파라미터 범위로 시작하되, 실제 런타임 측정으로 정한다.

단계별 후보:

| 단계          | 후보와 조건                                                                  |
| ------------- | ---------------------------------------------------------------------------- |
| 라지 티츄     | 선언/통과, 처음 10장만 입력                                                  |
| 교환          | 두 팀원에게 줄 서로 다른 카드의 순서 있는 쌍. 18×17=306개가 상한인 초기 상태 |
| 스몰 티츄     | 첫 내기 전 합법적인 시점마다 선언/보류                                       |
| 내기          | 합법 조합/패스, 봉황 대체·의무 소원 포함                                     |
| 새 소원       | 세가 포함된 수에 대해 소원 없음 또는 2–A, 실제 서버 계약에 맞춰 생성         |
| 개·용         | 합법적인 상대 좌석을 행동 특징에 포함                                        |
| 폭탄 끼어들기 | 합법 폭탄/끼어들지 않기                                                      |

6인 공통 가중치를 쓰고 자신 기준 상대 좌석을 표현한다. 팀원 2명은 별도 슬롯으로 유지한다.
개/용/교환 대상을 단순히 가장 작은 장수로 고정하면 그 선택은 학습하지 못하므로 정식판에서 제거한다.

## 학습 목표와 절차

주 목표는 팀 점수 차이다. 첫 완주는 진단 지표이지 단독 보상이 아니다.

`G = (이번 라운드 우리 팀 점수 − 상대 팀 점수) / 1000`

±100/±200 선언, 획득 카드, 완주 보너스까지 엔진의 최종 정산을 그대로 사용한다.
1000으로 나누는 것은 크기 조정이며 clipping하지 않는다. 승패만 보상하거나 손패 감소에
큰 보상을 주면 실제 점수 목표와 어긋날 수 있다. 매치 승률은 별도 평가하고, 필요 시
두 목표의 우선순위를 명시한 별도 실험을 한다.

1. 합법성·가시 정보 테스트를 통과한 환경에서 자기 대국 trajectory를 생성한다.
2. 모든 학습 플레이어의 `(관측, 이력, 행동)`에 해당 팀의 실제 종료 `G`를 부여한다.
3. 초기 DMC는 MSE로 `Qθ`를 회귀한다. Huber 손실은 이상치 민감도를 비교하는 별도 후보다.
4. 행동 선택은 ε-greedy. 시작 제안 ε=0.1→0.02, Adam 3e-4, batch256,
   gradient norm clip1.0, L2 1e-5. 이 값들은 검증할 초기 설정이고 확정 최적값이 아니다.
5. 최근 정책 데이터 중심의 bounded buffer를 사용하고 정책 버전을 기록한다.
   과거 정책이 만든 결과를 현재 정책의 정확한 가치라고 간주하지 않는다.
6. 상대 풀: 최신 정책 40%, 과거 스냅샷 30%, 서로 다른 규칙 봇 20%, 다양성용 정책 10%를
   시작안으로 비교한다. 같은 비율이 최적이라는 보장은 없으며 상대 풀 효과를 따로 측정한다.
7. 파트너도 일부 대국에서 다른 스냅샷/규칙 봇으로 바꾼다. 상대 다양성과 파트너 다양성을 구분한다.
8. 사람 기록은 선택적 초기 모방/협력 적응에 사용한다. 승리 팀만 무조건 모방하지 않는다.
   사람의 실수·분포 변화·복제 편향을 확인하고, 자기 대국 성능과 분리해 평가한다.

중단·재개에 필요한 checkpoint에는 모델뿐 아니라 optimizer 상태, RNG, 정책/환경 버전,
샘플 수, 학습 seed, buffer 메타데이터를 저장한다. 현재 E0는 모델 파일만 저장하므로
optimizer까지 완전히 동일한 재개가 가능한 상태라고 주장하지 않는다.

## 과적합 방지와 평가 설계

네 개의 분리된 seed 영역을 고정 manifest에 기록한다: 학습 / 개발 검증 / 최종 평가 / 장애 회귀.
초기 패와 그 문양 재명명·좌석 회전·복사본 교환 변형은 같은 split에 둔다.
행동 행 단위 랜덤 분할은 금지한다. 한 라운드/매치의 이웃 행동이 양쪽에 들어가면 누수다.
사람 기록은 원래 식별자를 저장하지 않으므로 사용자 단위 독립성을 보장할 수 없다.
시간 분리도 현행 export에는 정확한 시각이 없어 불가능하다. 이를 숨기지 않고 데이터
수집 배치별 분리와 별도 사람 평가로 보완한다.

- 독립 학습 seed 최소 3개로 방향을 확인하고, 유망 후보는 5개로 재현성을 검사한다.
- 개발 검증은 최소 256개 짝지은 패부터 시작, 매 checkpoint 같은 비교군·패 사용.
- 최대 checkpoint 비교 횟수를 사전에 제한한다. 작은 검증 세트의 최고 기록을 무한히 고르지 않는다.
- 검증 향상이 5회 없으면 조기 종료/최적 checkpoint 복원. 개선 기준과 횟수는 manifest에 고정한다.
- 최종 평가는 선택된 모델을 고정한 뒤 1,000개 이상 짝지은 라운드와 별도 전체 매치로 시작한다.
  시간 예산이 부족하면 덜 실행한 개수를 그대로 보고하고 출시 판정을 보류한다.
- 같은 패에서 A/B 정책 교체, 좌석 회전, 동일 deck stream을 적용한다.
- 개별 행동을 독립 표본으로 세지 않는다. 최소 단위는 짝지은 패/매치이며, 학습 seed까지
  포함한 계층적 bootstrap 구간을 보고한다. 한 학습 seed의 1만 경기로 학습 재현성을 증명할 수 없다.
- 기존 봇, 최강 규칙 후보, 과거 모델, 독립 seed 모델을 각각 상대한다.
- 팀 구성: 모델3명 / 모델1+기존봇2 / 모델2+기존봇1 / 서로 다른 모델 혼합.
  봇끼리 결과를 사람과의 협력 실력으로 바꿔 말하지 않는다.
- dropout/L2는 보조 도구다. 새로운 상대·새 패·새 파트너에서의 성능 저하가 핵심 감시 대상이다.

보고 지표: 평균 라운드 점수 차이와95% 구간, 전체 매치 승률, pair win/tie/loss,
선언 빈도·성공률·선언으로 얻은 순점수, 삼인 선완주, 용 양도 손실, 혼합 팀 점수,
불법 수/무한 반복/비공개 정보 위반 수, 추론 p50/p95/최대 CPU·메모리.
평균 매치 최종 점수 차이와 평균 라운드 점수 차이를 같은 단위로 비교하지 않는다.

출시 후보 기준(프로젝트 제안): 불법 수·정보 누수 0, 기준 봇 대비 평균 라운드 차이의
95% 하한>0이며 목표 효과 +10점 이상, 전체 매치 승률도 악화되지 않음. 혼합 팀에서
뚜렷한 성능 퇴행이 없어야 한다. 최종 평가를 보고 가중치를 고쳤다면 새 최종 평가 세트를
써야 한다. 모델이 통과하지 않으면 기존 봇을 유지한다.

## 사람 기록과 운영 추론

현재 수집기는 동의한 사람의 관측/행동/결과를 보관하는 작은 비공개 버퍼다.
80KiB는 프로젝트의 보수적 상한이며 SQLite Durable Object의 제품 한계라고 주장하지 않는다.
현재 스키마에는 충분한 공개 행동 시퀀스가 없어 GRU 학습 자료로는 부족하다. 다음 스키마에서
닉네임 없는 공개 이벤트와 관측 시점의 이력 구간을 추가하고, 잘린 기록은 표시한다.
부분 기록으로 완전한 replay를 복원하지 않는다. 학습 전 필수 특징·결과가 없는 예시는 제외한다.
상세 보존/내보내기는 [TRAINING.md](TRAINING.md)를 따른다.

학습은 개발 장비에서, 운영은 고정 모델 추론만 한다. TensorFlow.js는 현재 개발 의존성이다.
[공식 TensorFlow.js 자료](https://www.tensorflow.org/js/tutorials)는 Node/브라우저 사용을
설명하지만 우리 Workers 호환성을 보증하지 않는다. 필요 시 지원되는 표준 ONNX 런타임을
비교하고, 변환 전후 같은 관측에 대한 점수/행동 오차를 확인한다. 대형모델의 결과를 작은
모델에 증류하는 것은 추후 선택지이며, 작은 모델도 독립 대결을 다시 통과해야 한다.

[Workers 한도](https://developers.cloudflare.com/workers/platform/limits/)와
[Durable Objects 한도](https://developers.cloudflare.com/durable-objects/platform/limits/)는
실행 위치별로 구분한다. 라우터의 한도를 게임 DO에 무조건 적용하지 않는다. DO가 여러 방을
처리하는 현재 구조에서는 긴 동기 추론이 다른 방의 처리를 지연시킬 수 있으므로 실제
최대 후보 수에서 추론을 측정한다. 내부 목표 p95 20ms 미만을 시작점으로 삼되 무료 요금제,
실제 호출 경로와 작업량을 측정한 뒤 조정한다. 모델 오류·비정상 점수·예산 초과는 기존 봇으로
fallback한다. 유료 플랜이나 외부 GPU 서비스는 자동으로 신청하지 않는다.

## 실행 순서와 완료 증거

| 단계         | 작업                                                       | 산출물·통과 조건                                                                |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------- |
| E0 현재      | 2시간 규칙 후보 실험, 별도 작은 REINFORCE 학습             | 실제 terminal 상태, 모델 해시 변화, 검증/평가 구분. 강한 모델이라는 보장은 없음 |
| E1 환경      | 관측 경계·문양 포함 행동 생성·모든 게임 단계·폭탄 기회     | 작은 손패 완전대조, 시뮬레이션/서버 동작 일치, 숨겨진 패 변조 불변 테스트       |
| E2 기준 학습 | DMC MLP, 이력 없는 모델, 기존 REINFORCE를 동일 예산 비교   | config+seed+시간+행동 수+모델+학습곡선, 최소3학습 seed                          |
| E3 개선      | GRU 이력, 선언/교환 단계, 과거 상대/혼합 파트너            | 한 요소씩 추가한 ablation과 검증 개선. 조합도 다시 검증                         |
| E4 확정 평가 | checkpoint 고정 후 새로운 패·상대·팀 구성                  | 짝지은 결과와 신뢰구간, 성능·협력·자원 기준 통과                                |
| E5 운영      | 작은 고정 모델, fallback, 모델 버전 표시, 기록 schema 호환 | Worker 통합·재시작·실제 CPU 검증, 배포 결과 확인                                |

2시간은 E0의 제한된 실험 시간이다. E1 이후의 작업 시간을 근거 없이 약속하지 않는다.
먼저 30분 처리량을 측정해 목표 학습 스텝/게임 수에 필요한 시간을 산정한다. 참고 논문의
고성능 결과는 여러 날의 학습과 별도 자원을 사용했으므로, 같은 품질을 이 장비에서
2시간 안에 달성한다고 가정하지 않는다.
